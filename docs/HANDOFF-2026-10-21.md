Restore is deferred a microtask so same-target handoffs (lift→expand, StrictMode) don't snap. An invisible **spacer** (same classes, measured size, no `data-vt-name`) holds the layout slot so siblings don't shift. Target lookup retries ~30 frames (launcher jumps). 3. **Backdrop**: one rule set in `walkthrough.css` keyed on `data-beat-kind`; blur is **8px** (user tuned 40 → 12 → 8), tint `rgba(0,0,0,0.6)`.
4. **Ask HOAi panel** (`src/chat/AskHoaiPanel.tsx`): `position: fixed` in every form with explicit `left` (never `auto`) so sidebar ↔ focused morphs over 700ms; sidebar z 190 (above the z-180 white canvas, below `.wt-root`). Welcome → thread morph is a GSAP (`useGSAP`) timeline; Send ignored while it's in flight; scripted conversation timers all cleared on scene exit; reset deferred 700ms past the exit morph.
5. **Cursor** (`src/walkthrough/beats/CursorBeat.tsx`): portaled to `<body>` at z 400; waits for running finite CSS animations (≤1.5s) before starting; measures each stop when it sets off for it (later stops may be rendered by earlier clicks); per-stop `holdMs`; `releaseStage` / `hideStage` callbacks.
6. **Sticky stage** (`src/walkthrough/WalkthroughOverlay.tsx`): a lift/expand stays mounted through a following `annotate` or `cursor` beat; backdrop follows the staged beat. A cursor stop with `hideStage` dissolves the staged element in place (still lifted, blur up); `releaseStage` lets it go (it snaps back to its slot as the blur fades). Both last only for that beat visit.
7. **Back/forward semantics** (`src/walkthrough/cursor.tsx` reducer): stepping back across a scene boundary onto a cursor beat sets `replayOnAdvance` (scene `appState` resets the app to the scene's start, undoing that click), so the next advance replays it. Cursor beats with `replayOnBack: true` (self-reverting, e.g. the payment demo) replay after a within-scene back too.

## Gotchas learned

- **HMR can strand lift state.** Editing `useLiftTarget.ts` while the preview sits on a lifted beat can leave a stray spacer or pinned styles. Ask the user to hard-reload (Cmd+Shift+R) before judging a lift bug. (Offered, not built: a sweep that removes orphaned `[data-wt-lift-spacer]` on claim.)
- Scene `appState` is the scene's **start** state and is re-applied on every scene change (re-keys `NewResidentFlow` for onboarding screens). If something "disappears" on scene entry, check the scene's appState first.
- The overlay's `.wt-caption` is `display: none` — captions don't show.
- jsdom has no layout, transitions, or `getAnimations`; visual behavior must be confirmed by the user in the browser.
