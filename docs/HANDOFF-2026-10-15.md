## Open problems with proposed next steps

### Walkthrough: disjointed animations

**What's seen** (confirmed from screenshot during this session, with cursor at the `annotate` beat of scene 0):

- The caption types correctly at top.
- A **tiny blue dot** sits in the middle of the viewport — the annotate arrow with both endpoints set to `VT.BoardTaskCurrent` (a placeholder from Task 14, called out in the plan's deferred-minor list).
- The staged detail card is now present (fix `ce56980`), so the dashboard behind is dimmed with the expanded detail on top. That part is good.

**What still feels wrong** (triage, in impact order):

1. **The `lift` beat renders an empty stage slot.** `src/walkthrough/beats/LiftBeat.tsx` mounts an empty `<div>` with `view-transition-name: X` and sets the scene element's `visibility: hidden`. The browser morphs the before-image during the transition, but once the transition completes, the user sees an empty box at center. If the presenter pauses on `lift`, this is a dead frame. Options:
   - (a) **Transform the real scene element in place**: on lift, set the scene element's style to `position: fixed; top: 50%; left: 50%; transform: translate(-50%,-50%) scale(1.4);` and clear it on unmount. No stage slot, no visibility toggle. The browser VT morph treats this as "same element, new box" and animates. This is architecturally the cleanest VT pattern and avoids the empty-slot problem entirely.
   - (b) **Give `lift` a `preview` content prop** (ReactNode) that renders inside the slot — like a mini version of the Expand content.
   - (c) **Fold lift into expand** — treat them as a single beat kind with two scale states. Dropping `lift` from the beat DSL would simplify sequences but is a schema change.
   My recommendation is (a). Implementation sketch: `LiftBeat` becomes a `useLayoutEffect` that mutates `scene.style` on mount and restores on unmount. No stage slot. Open question: this uses the same `view-transition-name`, so there's no name collision concern. Test: write a jsdom test verifying the inline-style mutation + cleanup.

2. **Annotate arrow in `boardActions` is a zero-length placeholder.** Spec acknowledged this during Task 14 — the arrow endpoints need real `data-vt-name` targets inside the `BoardActionStageDetail` component. Fix: open `src/walkthrough/stage-content/BoardActionStageDetail.tsx`, add VT constants for the timeline block and the Approve button, tag both elements with `data-vt-name` and `style={{ viewTransitionName }}`, and update the `annotate` track in `scenes/boardActions.tsx` to reference the new names.

3. **Caption position collides with staged content.** Currently caption is bottom-centered via `.wt-caption` in `walkthrough.css`. On lift/expand beats the staged content is centered too — caption + card can crowd each other on short viewports. Low priority; adjust `.wt-caption` to `bottom: 24px` and reduce max-width if it's visibly bad.

4. **The 2 failing keyboard tests** (`advances on ArrowRight`, `toggles HUD on '.'` in `src/walkthrough/__tests__/keyboard.test.tsx`) still fail. Verified in Task 16 review as a React 19 strict-mode + `fireEvent(window)` / `renderHook` scheduling race — production behavior fine. Fix cost: wrap each `fireEvent` call in `await act(async () => { fireEvent.keyDown(window, ...); })`.

### AskHOAi reopen pill: "looks bad still"

User flagged this after `0ffbf3d`. Possible root causes (needs user clarification):

- **Visual style mismatch** — the sidebar is a quiet nav with icon+label rows. The solid blue filled pill reads as alien. Options:
  - Match the Quick Actions outlined style (border, blue text, white background) instead of solid blue.
  - Make it a NavItem-style row (icon + "Ask HOAi" label), same height and padding as other nav items.
  - Move it OUT of the sidebar entirely — e.g., as a floating button in the top-right of the main content area that only appears when the panel is collapsed.
- **Placement** — "below Calendar" was the user's exact ask, but visually it may conflict with the Board Actions subsection header that sometimes appears below Calendar (when `dashboardView === "board"`). Try moving above Quick Actions, or into the bottom section of the sidebar (near profile/logout).
- **Spacing** — the `mt-[6px]` is a hack; the nav list uses `gap-[13px]` on its wrapper. The pill may be getting double gap. Clean up the layout rhythm.
- **Icon alignment** — the extracted `AskHoaiIcon` was positioned by cropping the wordmark viewBox from `73 0 22 21`. Verify it visually centers in the pill; may need a `translate` adjustment or a tighter viewBox.

**Suggested first step for the next session:** ask the user which of the above they want ("looks bad" is ambiguous), then do a small focused redesign pass. Don't just tweak px values.
